# Shared persistence contract

`Store(data_dir)` owns `business.sqlite`, WAL, foreign keys, append-only events, messages, immutable artifacts and short transactions. All public methods are synchronous, safe across processes (each uses its own SQLite connection). Use `asyncio.to_thread` for potentially contended calls.

* `project(id)`, `projects()`, `create_project(payload)`, `update_project(id, **changes)`.
* `lines(research_id)`, `update_line(research_id, line_id, **changes)`, `snapshot(id)`.
* `put(kind, object_id, data, research_id=None)`, `get(kind,id)`, `list(kind,research_id=None, **filters)`, `patch(kind,id,**changes)`.
* `emit(research_id,type,payload=None,**refs)`, `events(id,after=0,limit=500)`.
* `create_conversation(research_id,conversation_id,**fields)`; `create_message(research_id,conversation_id,sender,content_markdown,**fields)`; `messages(conversation_id,before=None,limit=50,q=None,at_seq=None)` and `edge_messages(research_id,edge_id,before=None,limit=100,q=None,at_seq=None)` return `{items,next_cursor}`. `source_event_id` deduplicates messages. `at_seq` filters first visibility before paging and reconstructs body/status/metadata from durable events up to the cutoff; historical `q` searches that reconstructed body, never its future final content.
* `upsert_stream_message(research_id,message_id,conversation_id,sender,full_content,*,content_version=1,source_event_id,**fields)` stores actual cumulative text and deduplicates `chunk_id`. Empty initial text creates no row. First text atomically creates one message/cursor, `message.started` metadata, and the first actual `message.delta`; subsequent deltas append suffixes. A larger content version may replace text with `replace=true/full_content`.
* `complete_stream_message(message_id,full_content,status='complete',source_system='dsh',source_event_id=None,**fields)` replaces the same row with the authoritative final body/metadata. Completed or interrupted events carry the full message and `replace=true`. Interrupted streams never reopen; `sync_stop` also interrupts all still-open streams transactionally. Row `event_seq` is first visibility, `latest_event_seq` is its newest update; replay reconstructs text from each message's events rather than exposing a later final body at an earlier cursor.
* `add_task(research_id,kind,payload,idempotency_key=None)`, `pending_tasks(limit=100)`, `claim_task(id,owner)`, `finish_task(id,result=None,error=None)`.
* `register_artifact(research_id,path,media_type='application/octet-stream',**fields)` accepts only files inside data_dir, computes size/hash; `artifact(id)` resolves with path confinement and verifies hash on download.
* `commit_verification(cycle_id,submission_version_id,report,execution_generation,control)` stages immutable candidate, obtains durable ControlClient confirmation and applies counter/outbox exactly once. Submission document must be kind `submission`, cycle kind `cycle`. Report carries `passed: bool`, `checks`, `supported_conclusions`, `unsupported_conclusions`, and `spec_id/code_version/run_ids` matching submission when provided.
* `dispatch_outbox(control,limit=100,research_id=None)` drains a bounded, project-interleaved batch and returns `{delivered,cancelled,pending}` outbox IDs. It validates the committed Verify receipt, current cycle, generation, deadline and independent Control gate. The real handoff message is idempotent by `verification_dispatch/submission_id`; one transaction acknowledges every recipient inbox, creates `message_delivery` receipts, materializes the exact `submission_id + ':boss'` task when required, and marks the outbox `delivered`. Ordinary failures feed the existing serial line graph and create no line task. A crash before acknowledgement reuses the persisted message; unavailable destinations stay pending and do not prevent other projects' delivery. Known stopped or stale destinations are cancelled.
* `consume_inbox(research_id,recipient_id,consumer_id,cycle_id=None,control=None)` returns actual delivered verification context plus its message and durable receipt. Recipients are `line-XX/exploration`, `line-XX/critic`, or `boss`. Use stable graph/checkpoint consumer IDs: a retry receives the same consumed entries, while another consumer cannot steal them. Consumption records `handoff.consumed` and acknowledges the delivery receipt under the current Control gate.
* `commit_boss_decision(research_id,decision_task_id,decision,control)`, `write_memory(research_id,boss_decision_id,update_batch_id,updates,base_memory_version,control)` require confirmed boss decision and generation/deadline fence.
* `apply_boss_effects(research_id,decision_task_id,line_id=None,snapshot=None,control=None)` confirms immutable downstream work then atomically materializes assignments, epochs/cycles, tasks and report snapshots once. It returns `status`, `task_ids`, `cycle_ids`, `finish_line_ids`, `dispatch_allowed`. Finished lines/projects carry `finish_requested`. Already applied decisions never reset counters or increment epochs on replay; stopped projections create no dispatchable work.
* `commit_report(research_id,report_id,report,control)` publishes a report and completion event only after a durable independent receipt. Pending results remain diagnostic candidates. Report replay is idempotent. Default artifact IDs derive from research/content/purpose, and registration returns the previous immutable metadata for repeated content.
* Utilities `now()`, `new_id(prefix='')`, `utcnow()`, `canonical(value)`.

`CredentialService(data_dir,store).get_secret(provider_id)` is internal runtime-only. It reads environment injection or Windows DPAPI protected bytes; never persist its return value to workflow state or pass it to tools/experiments.
