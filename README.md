# AutoResearch

在本机运行的自动化科研工作台。实现依据为 [design.md](docs/design.md) 与 [technical-implementation.md](docs/technical-implementation.md)。

包含 React 工作台、FastAPI API、LangGraph 编排 Worker、独立 Control Supervisor、独立 Runner、SQLite 持久化，以及官方 DeepSeek Harness Python SDK 适配。研究数据默认保存在项目下的 `data/`，服务只监听回环地址。

## 安装与启动

当前主要验证环境为 Windows、Python 3.13、Node.js 24。Python 要求 3.12 及以上；前端构建要求 Node.js 20.19+ 或 22.12+。安装脚本需要 [uv](https://docs.astral.sh/uv/)。

```powershell
cd C:\Users\64379\Desktop\Programs\AutoResearch
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
.venv/Scripts/python.exe scripts/launch.py
```

打开 [本机工作台](http://127.0.0.1:8000)。也可运行 `start.ps1`。启动器先开放独立停止通道，再启动网页 API、Runner 与 Worker。通过 Ctrl+C 正常退出启动器时，会终止其管理的在途工作。

前端已经构建时，日常运行只需要 Python 与官方 DSH 运行时，无需再启动 Vite。首次安装下载官方 Windows 运行时可能较慢；可设置 `$env:UV_HTTP_TIMEOUT='300'` 后重试安装。

默认端口：网页/API `8000`、Control `8766`、Runner `8767`。可以通过启动器的 `--port`、`--control-port`、`--runner-port` 改变。已有端口被占用时启动器会拒绝覆盖现有进程。

```powershell
# 独立数据目录，不与已有研究混用
.venv/Scripts/python.exe scripts/launch.py --data-dir D:/ResearchData --no-browser

# 前端开发（API 保持运行）
cd apps/web
npm ci
npm run dev
```

## 开始研究

1. 在“模型与凭据”保存 DeepSeek API Key，测试连接。默认显示 DeepSeek V4.1 Flash，请求模型 ID 为 `deepseek-flash`。
2. 在“研究团队”设置研究线、各组人数、Verify 汇报周期与研究总时间。默认配置产生 18 个逻辑 Agent（含独立 Watch Dog）。高级配置可调整巡检间隔，默认 10 分钟。
3. 检查“计算资源”，创建研究时手动填写任务名称、研究内容、限制以及已有数据/代码目录。可以从按任务名显示的历史记录下拉菜单导入配置，名称单独填写。
4. 在工作台展开成员、选择节点或连线，查看讨论、交接、执行轨迹、实验、证据、记忆和报告。

官方模型服务地址为 `https://api.deepseek.com/anthropic`，DSH 实际请求 Messages 接口。旧配置中的官方根地址或 `/v1` 地址会在调用时兼容转换；自定义代理保留自己的路径前缀。连接测试也使用 Messages 接口，并显式关闭思考以完成最小文本响应检查；通过该测试不代表完整科研流程、工具或流式验收通过。

**真实研究**使用官方完整 SDK profile 和真实模型请求。缺少凭据、数据、依赖或运行能力时会进入阻塞状态，不生成虚构结果。

**演示模式**必须在创建时明确选择。Agent 回应来自标记的预设脚本；CPU 线性回归示例由真实本机进程运行。演示只能验证程序链路，不是题目的科研结论。

API Key 使用当前 Windows 用户的 DPAPI 加密，前端只显示掩码。可选环境变量 `DEEPSEEK_API_KEY` 由后端读取。更换凭据后，已有项目需要在阻塞提示中显式重新绑定凭据版本。不要把密钥写进题目、描述或代码。

## 运行规则

- 同一个群聊每次只有一名成员正式发言。开始时随机确定一次成员顺序并保存；提案、各轮审查和投票都沿用该顺序。取消意愿评分、热度及重复抽签，重启后继续原顺序。各独立研究组仍可并行。
- 新讨论采用[小组讨论与 God 定稿协议](docs/GROUP-DISCUSSION-AND-GOD-REDESIGN.md)：成员自由发言，可自行发起普通投票；普通投票统计选项和理由后继续讨论。
- 结束投票绑定完整产物，必须全员同意且推进方向一致。失败后全员各再发言一次才能重投；累计三次失败立即由 God 输出完整最终产物和推进方向，直接交接，无需再次总结或复议。旧 Issue 状态不再自动否决新版讨论和交接；真实执行及证据来源仍需验证。
- 普通投票和结束投票在聊天记录中展示议题、成员票、统计、绑定产物、失败次数和冻结状态，支持分页、搜索与历史回放。旧检查点继续使用旧协议，历史记录保持原义。
- Critic 可以交给 Implementation 或交回新 Exploration 讨论。Boss 用明确方向和操作列表组合安排继续研究、换方向、结束研究线及报告；已执行操作在重试时复用。
- 消息工具在同一事务保存正文、每位收件成员的收件箱和投递回执，并登记可恢复的通信回复任务。正式模型回合读取固定的收件批次；空闲接收方也会处理消息，回复不会直接形成科研决议或自动循环。旧方向的消息和回复不会进入新方向上下文。
- 历史协议的问题改类保留原有来源校验；新版不要求维护问题状态表。运行监控保存日志游标与固定观察窗口，重试不跳过新日志；已准入且确认清理的启动失败也形成失败包送 Verify。
- 首页可删除已完成、已终止或已隔离的运行记录；在“已删除”中恢复。删除只改变列表可见性，保留消息、证据、文件、检查点与停止记录。进行中的研究先终止再删除。
- 每条研究线固定绑定 Exploration、Critic、Implementation 和 Verify。Boss、Organizer 和 Paper 承担全局职责。
- 独立 Watch Dog 按项目配置定时巡检，健康或正常等待时不调用模型。确认停滞后，程序只提供研究线、任务、错误及本地路径，由 Agent 自行查数据库、日志和代码并在线修复。五种内置修复动作可选，也可使用原生本地工具。耗尽回合的恢复建立新的生成版本，保留原讨论与已收投票。组织图记录诊断和操作，巡检观察到实际进展后标为已修复。
- 仅有效、版本一致的 Verify 报告计轮。同一提交重放不重复计数。第 k 轮无论是否通过都只交 Boss；此前通过交 Boss，未通过同时交本线两个研究组。
- 固定实验方案不可由 Implementation 擅改。实现错误可以修复并保留版本；越界修改返回研究设计流程。
- Runner 确认正式实验因主机内存限额失败后，用原计划、代码与参数自动申请双倍预算，最多扩容重试两次，且不超过单实验可用总容量。排队沿用同一申请；每次运行保留独立授权、输出目录、日志与实际预算。GPU 显存错误、普通异常或含 OOM 的文字不会单独触发扩容。
- Organizer 只有具备可启动资源时才授权，任务返回原 Implementation。授权、启动和资源释放受事务、控制代次、进程退出证明约束。
- 只有 Boss 决议可以写共享记忆。报告使用冻结的证据快照，保留负结果、失败和验证边界。
- Paper 的时机由 Boss 的 `report` 方向或报告操作决定，允许无实验结果的阶段报告；Boss 引用的真实附件会随报告材料冻结并明确授权，不从可变目录或其他项目补取证据。
- 唯一预算为整个研究的总运行时间。排队、暂停和重启间隔均计时；各研究线共享原始截止时间。
- “暂停新增工作”等待安全边界，已有实验仍被监控。“立即终止”会关闭启动门禁并停止模型、工具及实验进程树。
- 停止不先等待业务库写入。界面分别显示执行退出、独立停止记录、数据库同步与资源对账状态。
- Control 重启后旧许可作废，原非终态项目被隔离。不能通过恢复命令重新启动已终止或到期研究；继续工作需新建研究。

## God 自动仲裁与恢复

组内聚焦讨论后仍无严格多数、审查无进展及规定的输出与任务冲突会自动进入 God 仲裁。God 使用每个请求独立的执行身份与会话，合法结果经过校验、持久化与应用后继续原流程；原始票型保留，仲裁不会伪造成员多数票。需要修订、取证或拆分时，工作台显示实际子任务与恢复进度。

组织图中的 God 节点可查看并发请求、独立会话、冻结上下文清单、处理动作及来源。只有已应用的结果显示“已采用”；历史回放依据事件游标展示当时状态。暂停、立即终止、方向版本、固定计划与项目总截止时间继续生效。

God 的流式与最终回复使用同一消息；未通过校验的尝试标明未采用与失败原因。旧记录中的重复副本在显示时合并，原审计记录保留。只有实际等待模型容量超过短暂阈值时才提示排队，同一调用不重复提示。

本机数据库短暂占用或流式记录暂时不可用时，Worker 会保留检查点，确认旧执行退出后自动重试；已保存的完整模型回合会复用。流式分片重试保持原编号，响应丢失不会重复追加。永久拒绝或缺少真实外部条件仍显示具体阻塞原因。

单个模型回合的输出纠错不设次数上限，包括讨论发言、投票、监控、Watch Dog 和 God 的字段修复、截断及响应协议重试。每次尝试和回执持久保存，重启复用已返回结果，尚在运行的执行继续等待回执；旧版本因三次限制耗尽的讨论可直接重试，已收票保持不变。服务异常继续退避，停止、暂停和项目截止时间始终优先；God 仍受单次请求的判决时限约束，监控在实验退出后停止纠错。

Critic 讨论陷入设计修订僵局时，God 可沿已登记路径请求同线 Exploration 以自己的身份修订，再交回原 Critic 逐项复审；原问题与票型保留，未解决必改项继续阻止冻结。Implementation 的配置声明与冻结计划不一致时，先向 Implementation 发起一次带具体差异的纠正；仍不一致才回到设计修订，不自动覆盖配置或放行代码。

Control 或 Runner 短暂失联会保留可恢复任务；已确认终止、控制日志损坏或明确拒绝仍关闭执行门禁。正式实验启动应答丢失时，根据原始执行身份接回正在运行或已有退出证明的结果。启动恢复遇到数据库占用会退避重试，启动器会在 Worker 意外退出后重新启动它并先完成状态对账。

补齐外部条件后，点击“重试阻塞任务”会开启新的恢复版本，重新读取输入并保留旧仲裁记录。Boss 并发更新同一记忆节点发生冲突时，会基于最新记忆重新审议；内部依赖会随上游验证和共享结果发布重新协调。这些恢复均沿用原项目截止时间。

跨研究线的基线、接口等内部依赖交由 Boss 协调，父任务等待时释放执行名额。只有 Boss 已确认、带有效来源的共享信息可以唤醒原组继续审查；唤醒不等于验收通过。所有未完成研究线均阻塞且没有可执行任务时，项目会显示阻塞状态。

设计与逐项验收要求见 [god.md](docs/god.md)，代码接入、已运行验证及验证边界见 [GOD-IMPLEMENTATION.md](docs/GOD-IMPLEMENTATION.md)。

## 官方 SDK 与工具权限

版本锁定为 `deepseek-harness-sdk==0.2.1rc2` 与匹配的 `deepseek-harness-runtime-bin==0.2.1rc2`。使用完整 `sdk` profile；不以裸模型请求替代 Harness。每个项目/Agent/方向代次保留独立会话，机器级 Organizer 有显式共享身份。

Watch Dog 使用 SDK 的 `danger-full-access` 模式，可调用原生文件、搜索、命令等工具读取和修复本地项目。首次提示包含业务数据库、检查点数据库、项目目录、代码仓库及 Python 路径，其他材料由 Agent 按需查询。诊断执行继续受项目停止、暂停、截止时间、方向和执行租约控制。

内置 scoped research 插件注册证据读取、共享记忆读取、真实消息发送和轻量 CPU 分析。轻量计算执行普通 Python，不限制导入、函数、属性、文件访问或子进程（含 NumPy、pandas、os），不要求空闲 1 核 CPU；证据提供只读文件路径，脚本自行解析；任意格式的结果文件自动登记，JSON 仅为可选预览。保留角色与证据身份校验、内存资源检查、进程树停止控制及项目总截止时间。常规科研角色的提示词要求仅在分配工作区写入，可只读访问用户提供的数据目录；轻量代码通过 workspace_dir/data_dir 获取这两个目录。用户选择的数据目录内全部文件均可读取，不按文件名、隐藏属性或格式过滤；目录范围校验继续生效。运行进程尚无操作系统级文件系统隔离，提示词约束不是不可信代码的安全边界。正式实验仍通过受监督 Runner 启动。

创建研究时指定的代码/数据目录可通过受限输入工具分页读取，读取的来源与内容哈希会登记为证据。工具拒绝越出该目录、凭据文件、内部运行数据及逃逸链接；Paper 与 Organizer 不直接浏览输入目录。

如果已经安装了**版本完全匹配**的官方 DSH CLI，可显式配置 `AUTORESEARCH_DSH_BIN` 使用官方 SDK 的公开 `dsh_bin` 参数。适配层会核对版本，不会静默退回其他模型或模拟模式。未设置时使用 SDK 打包运行时。

```powershell
# 可选：仅用于已经存在的匹配版本官方运行时
$env:AUTORESEARCH_DSH_BIN = 'C:/Users/64379/AppData/Roaming/npm/dsh.CMD'
.venv/Scripts/python.exe scripts/probe_dsh.py
```

仅做最小模型连接测试不会证明工具、流式和恢复能力全部通过；SDK 本地协议测试也不等于已通过真实 DeepSeek 服务验收。当前验证记录见 [IMPLEMENTATION.md](docs/IMPLEMENTATION.md)。

## 数据与故障处理

`data/business.sqlite` 为业务库；`data/checkpoints.sqlite` 为独立 LangGraph 检查点库；`data/control/` 保留停止墓碑与确认记录；项目产物、会话、日志在各自子目录追加保存。下载仅允许已登记且 SHA-256 一致的产物。

服务日志为 `data/control.log`、`api.log`、`runner.log` 和 `worker.log`。停止日志损坏、旧进程状态不明、数据库故障时，启动门禁保持关闭。可以导出已有记录；不要删除停止墓碑以尝试恢复研究。

备份时先通过启动器停止所有服务，然后一起复制整个数据目录，保留业务库、检查点、停止记录和产物。DPAPI 凭据绑定 Windows 用户，迁移账户或机器后应重新配置密钥。

## 执行与并发恢复

实验不再做依赖预检查，也不因修复后的源码相同而跳过执行；实际异常、日志和退出码交给 Implementation 修复。Implementation 只需提供源文件和入口，说明、方案哈希与配置副本可省略；实验结果不要求固定文件格式。工作区路径、冻结科学设置、停止控制与资源授权继续生效。超过机器总容量的申请会携带资源差额返回 Implementation 调整执行方案，不再等待到期。

模型并发输入不设固定最大值。项目使用自己的并发设置，服务端只有绑定接口、模型及凭据版本的实测容量限制，不再默认限制为全机器 4 请求。运行以下命令可重新测试并保存 75% 余量后的服务容量；测试会产生真实模型请求，报告不含凭据或模型正文：

```powershell
.venv/Scripts/python.exe scripts/benchmark_model_concurrency.py --levels 1,8,16,32,64,128,192,256 --apply
```

短请求压测只用于容量参考，不能视为长上下文、流式或完整研究的吞吐保证。变更接口、模型或凭据后旧测量不再用于限制。

普通模型输出提取所需字段并容忍额外说明。程序负责填写系统编号、版本、截止时间和哈希；模型仅返回科学内容与业务判断。Verify 可引用来源可追溯至当前提交的同线计算产物。研究线数、成员数、汇报周期和实验并发不设任意最大值，实际执行由资源与服务容量协调。
