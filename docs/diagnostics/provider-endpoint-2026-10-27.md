## 根因

程序默认把 `https://api.deepseek.com` 作为完整 DSH 的模型地址。锁定的官方 DSH 0.2.1rc2 使用 DeepSeek Messages 协议，实际拼接 `/v1/messages`；官方 Messages 根地址应为 `https://api.deepseek.com/anthropic`。原连接测试却使用 `/chat/completions`，因此即便连接测试成功，也没有验证研究真正使用的接口。

错误分类还把 404 变成笼统的 `model_execution_failed`；子进程输出受 SDK 编码设置影响，中文错误文案出现乱码，使界面无法准确解释问题。

## 修复

- DSH 和连接测试共享地址解析规则；官方根地址及旧 `/v1` 自动转换到 `/anthropic`，保留自定义代理前缀，避免重复 `/v1`。
- 新配置默认使用正确地址；本机已保存配置也已更新，密钥与凭据版本保持不变。
- 连接测试改为同一 Messages 路径、认证请求头与响应合同。真实测试发现默认思考会耗尽 16 个输出 token，故最小测试显式关闭思考，仍要求合法非空文本响应。
- 按官方错误结构区分地址、请求、额度、凭据、限流、连接与超时，记录安全的状态码和提供方错误码；不透传原始错误正文或请求头。
- 子进程使用 ASCII JSON 传输，反序列化后保留完整中文，不受控制台编码变化影响。
