# 多余检查与约束复查（2026-10-30）

范围：当前工作区，包括审查前已有的未提交改动。本轮只审查与本地复现，没有修改业务代码、没有调用模型 API、没有新增 commit。

确认 11 项：2 项 P1、9 项 P2。下列优先级按触发后的影响评定，不表示所有项目都会遇到。

## 1. [P1] 无法启动的排队请求仍会挡住其他项目

位置：`backend/runtime/runner.py:261-264`。

当前申请会检查其所属项目的实验并发，但检查“更高优先级请求是否应先执行”时，没有检查那个请求所属项目的并发是否已满。于是不可启动的请求也能否决其他项目。

复现：机器配置 8 核，A 项目并发为 1；A1 获批占 1 核，A2 因本项目并发已满排队；B1 只申请 1 核，仍被 A2 拦下。结果依次为 `granted / queued / queued`，资源远未用满。A1 若持续运行，B 也会继续无谓等待。

建议：排序只比较当前确实可获批的请求；复用一套资源和项目并发判断，删除这条不完整的额外否决路径。

## 2. [P1] 监控回复抄错哈希会阻塞整条研究线

位置：`backend/graphs/engine.py:1018-1019`；后续阻塞处理位于 `backend/runtime/worker.py:306-344`。

程序已把模型回合绑定到固定日志窗口，却仍要求模型原样返回 `evidence_log_hash`。在请求提前停止时，即使规则为合法的 `execution_unusable`，抄错哈希也会抛出 `invalid_early_stop`。该检查发生在普通模型输出恢复流程之外，该错误也不属于自动重试类别，最后研究线进入 blocked。

复现：合法规则 + 错误哈希，得到 `invalid_early_stop`，`retryable_failure` 返回 None。

建议：由程序记录该回合对应的窗口和哈希，取消让模型回填并校验哈希。停止条件仍可依据计划和实际日志判断。

## 3. [P2] 轻量计算在代码执行前强行解析证据格式

位置：`backend/runtime/light_cpu.py:139-141`。

所有证据都先按 UTF-8 读取；JSON/CSV 还由框架提前解析，再整体写入 inputs.json。`.npy`、图片、Parquet 等有效二进制证据会在用户脚本执行前失败，脚本无法自己选用对应库读取。

复现：登记合法 NumPy `.npy` 文件后传给轻量工具，结果为 `execution_failed`、`pid=None`、UTF-8 解码异常。

建议：提供完整性校验后的只读文件路径和元数据，让脚本选择读取方法。文本预览可以按需生成，不应成为准入条件。这样也能避免大 CSV 在监督进程之外被全量载入和重复复制。

## 4. [P2] 计算已完成，却因结果不符合自动 JSON 转换而报执行失败

位置：`backend/runtime/light_cpu.py:153-167`。

包装器只支持 JSON 原生类型及特定 NumPy/pandas 类型。普通 Python 对象即使有效，例如 `Decimal('0.15')`，也会在脚本已经算完后抛错，使整个任务变为 execution_failed。

复现：脚本先输出 CALCULATION_COMPLETE，再把 Decimal 赋给 result；确认计算完成，但包装器报 `Unsupported result type: Decimal`，最终状态为 execution_failed。

建议：把“计算退出状态”和“结果展示转换”分开；允许显式输出文件并登记产物。无法自动转 JSON 时报告转换局限，而非要求重跑计算或强行改变科学数据类型。

## 5. [P2] Verify 不能引用自己计算出来的派生证据

位置：`backend/graphs/engine.py:263-271`。

execution_checks 的引用范围被固定为提交时已有的 run/artifact。Verify 使用已有原始预测计算均值、置信区间或显著性检验后，新产生的 light_cpu_result 不在旧清单中，因此不能作为执行验收证据。

复现：派生产物确实登记于同一研究线，source_evidence_ids 指向提交中的原始产物，source_exists 为 True；依然被拒绝。

建议：允许来源可追溯到本次提交的验证派生产物。保留研究身份、真实来源与完整性检查，取消“必须在提交时就存在”的时间限制。

## 6. [P2] 修复路径还保留已取消的 .py 后缀限制

位置：`backend/graphs/engine.py:297-300`。

普通 Implementation 已支持无后缀 Python 入口，God 修复和拆分后的验证仍要求 entrypoint 以 `.py` 结尾。同样的实现，在正常路径可以接受，进入修复路径却被拒绝。

复现：`files={'main': 'print(42)'}, entrypoint='main'` 普通验证通过，修复验证失败。

建议：删除后缀检查，并统一正常与恢复路径的文件校验。工作区路径和实际入口存在性即可决定此处能否继续。

## 7. [P2] 要求模型原样抄回程序已知的计划身份和时间

位置：`backend/graphs/engine.py:248-251`。

spec_id、version、deadline_at 已由当前任务决定，却仍要求模型回填，并按原始字符串完全相等校验。相同时间用另一种合法 ISO 表示也被当作身份不匹配。

复现：只把截止时间末尾的 `Z` 改为等价的 `+00:00`，计划即被拒绝。

建议：这三个程序所有的字段在接收模型科学内容时统一注入。内部持久化和执行绑定仍保留版本检查，不再把复制元数据变成模型的任务。

## 8. [P2] 无关额外字段让整个有效模型回复被拒绝

位置：`packages/contracts/research.py:16-17`。

除 Implementation 等少量例外，所有普通科研输出继承 extra='forbid'。Review 内容和决定均有效，但多返回一个 confidence 等说明字段，就会触发 ValidationError，后续可能进入恢复或仲裁。

复现：合法 Review 加 `confidence: 0.95` 得到 extra_forbidden。

建议：普通科研内容忽略或单独归档未知字段；继续校验必要决策字段。程序控制对象、命令身份和授权载荷可继续保持严格字段集合，无需整体放宽。

## 9. [P2] 已确定下一位发言人，仍要求所有成员重新评分

位置：`backend/graphs/discussion.py:105-117`。

score_members 每次都请求全组，包括本轮已经发过言、没有资格再次发言的成员。即使只剩一个可发言者，也必须等待所有评分；任意无用评分失败，会连带中断讨论。

复现：A、B 已发言，只剩 C；实际仍调用 A、B、C 三次评分。让 A 评分失败，整个选人阶段失败。

建议：只给当前实际可选成员评分；只有一个候选时直接选择。无需改变现有发言选择算法，也不影响全员正式参与讨论。

## 10. [P2] 按通用文件名猜测敏感信息，误伤正常数据目录

位置：`backend/adapters/inputs.py:50-53`。

保护规则按路径任一部分的名字拦截，把 token/tokens 等通用词当成凭据目录。用户明确选择的数据目录下，正常 NLP 分词数据也会被隐藏和拒绝读取。

复现：`tokens/train.csv` 只有 word,count 两列，却在 list 中完全消失，resolve 也拒绝。

建议：删除 token/tokens 这样的泛化名称猜测，收窄到明确的凭据文件或位置；保留用户授权目录范围、路径越界和实际凭据保护。

## 11. [P2] 仍有一组与资源和算法无直接关系的硬编码配置上限

位置：`apps/api/main.py:36-43`、`apps/api/main.py:57`、`apps/web/src/NewResearch.tsx:11-13`。

目前正式实验并发最多 16，研究线最多 16，Exploration/Critic 成员各最多 8，Boss 成员最多 9，强制汇报周期 k 最多 20。这些数字未与机器资源、模型实测容量或算法边界绑定。

复现：向 Team 分别传入 experiment_concurrency=17、n=17、m1=9、boss_members=10、k=21，都被固定上限直接拒绝。

建议：删除这些固定最大值，保留正整数校验。正式实验由资源服务控制，模型请求继续受项目设置与实测服务容量控制；k 由用户决定汇报频率。界面渲染大量节点的性能问题应由分页或按研究线展示处理。

## 复现范围与未列入的问题

本地复现脚本：`.test-data/redundant_checks_review.py`。脚本使用隔离数据库、模拟资源容量和少量真实 Python 子进程，11 类情形全部复现；没有启动完整真实研究，也没有请求付费模型。仲裁、监控、讨论的部分复现直接调用相应方法，后续工作流影响通过调用路径核对。

本轮没有把用户停止、总截止时间、项目身份、路径越界、重复执行防护、进程退出证明、资源不超卖、证据完整性或冻结科学设置列为应取消的检查。

512 MiB 轻量计算额度、DSH 精确版本锁定、仲裁重试预算也有可配置化空间，但现有文档明确保留了这些策略；它们与本轮已经确认的误拦截分开讨论，未计入上述 11 项。
