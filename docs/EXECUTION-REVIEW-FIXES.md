## AutoDL 实测

使用本机已配置的 AutoDL 服务、DeepSeek-V4.1-Flash 与现有凭据，发送真实 Messages 请求。每个请求要求短文本响应，并关闭思考；不记录密钥或响应正文。

| 并发 | 完整文本响应 | 说明 |
|---|---|---|
| 1、8、16、32、64 | 全部成功 | 首轮逐级测试 |
| 96 | 96/96 | 复测 |
| 128 | 128/128，两轮均成功 | 两轮 P95 分别约 2.53 秒、3.18 秒 |
| 192 | 191/192 | 均为 HTTP 200，其中 1 个没有有效文本 |
| 256 | 254/256 | 均为 HTTP 200，其中 2 个没有有效文本 |

以两轮均完整成功的 128 为基准，留出 25% 余量，将当前服务容量限制保存为 **96**。这是短请求的保守运行基准；没有测出服务商的硬并发上限，也不能据此断言空回复一定由并发引起。长上下文、流式输出或服务负载变化时，实际容量可能降低。

容量记录保存在本机 provider 的 `concurrency_benchmark` 字段，绑定接口、模型及凭据版本；改变这些设置后旧记录不再参与限制。没有有效测量的服务不套用固定的全局并发上限。项目设置可以进一步降低并发。

可使用 `scripts/benchmark_model_concurrency.py --apply` 重新测试并保存。该命令会产生真实 API 请求；默认首次遇到不完整响应即停止提高负载。
