观察维度Agentic Scientist / v3AutoScientistsEvoScientist
最核心的组织单元受契约约束的研究循环。worker 内先提出假设，再执行与验证。围绕方向形成的团队。分析与实验角色通过论坛、队列和公共状态协作。论文中的研究、实验、记忆三类 agent；想法搜索与代码搜索相连。
谁决定下一步流程编排器管理阶段、预算与 worker；局部循环依据契约和评估结果推进。团队参与方向讨论；运行层仍有协调器和 monitor，负责组队、调度等。研究与实验 agent 各自推进搜索，记忆 agent 提炼可复用经验。
共享什么在研究循环边界交换提炼后的记忆和结论，原始产物保留在 worker 目录。论坛、团队名册、实验队列、失败记录，以及当前最优代码 champion。分别保存选题经验与实验经验，并在相关的后续任务中检索。
失败怎样被利用保留尝试记录；实现正确、rubric 完成、分数变优是不同判断。回写实验与死路记录；停滞后的重组或停止取决于运行策略。把轨迹提炼成对想法和实现的经验，影响以后搜索；记忆也可能带入偏差。
最值得移植任务契约 + 可核查产物 + 主张对应证据。
研究可信度		显式共享状态 + 任务认领 + 可调整的团队结构。
并发协作		区分科学结论和工程经验，建立有出处的长期记忆。
跨任务积累
不能直接推出通过 rubric 就等于科学结论正确，或自动生成评估器一定有效。动态组队必然优于固定团队，或所有任务都应无限运行。积累记忆必然提升泛化，或“自进化”意味着在线更新模型权重。
01

先固定「怎样算证据」

给每次实验绑定假设、代码版本、数据划分、预算和评估协议。让 Boss 看结构化证据，而不只看各组总结。

02

再设计「怎样协作」

保留探索与质疑分工，但补上任务认领、共享结果、计算资源与停止规则。动态组队应由需求和实测收益驱动。

03

最后决定「怎样记住」

清空上下文不应清空实验历史。科学结论记适用条件，工程经验记环境版本；都要能追溯、修正和失效。

DESIGN DIRECTION

对当前设计，建议先借鉴 v3 的证据流程，再吸收 AutoScientists 的协作状态管理，随后加入 EvoScientist 的经验记忆。这是一条实现顺序建议，不是三套系统的性能排名。
