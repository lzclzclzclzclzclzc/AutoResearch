# AutoResearch 自动化科研

2026-10-31 实施更新：新讨论以 [小组讨论、结束投票与 God 最终仲裁](./GROUP-DISCUSSION-AND-GOD-REDESIGN.md) 为准。普通投票只提供讨论材料；结束投票须全员同意且方向一致，失败后全员各再发言一次，累计三次失败由 God 直接定稿。新版不再以旧 Issue 状态或再次模型总结阻断交接。Critic 可以交回新的 Exploration 实例；Boss 可以用一个操作计划组合安排研究、换方向、结束及报告。两类投票均在聊天记录中显示。下文冲突规则只适用于旧协议及历史记录。

本版依据 2026-10-25 的新增需求更新：人类可以随时终止整个研究，包括正在运行的实验；运行预算只限制整个研究的总运行时间。本文确定角色功能、研究交互和实验约定；多 Agent 架构、调度、持久化和故障恢复详见[技术实现方案](./technical-implementation.md)。

## 一、组织结构与基本约定

共有 n 条研究线，n 可配置。每条研究线的角色固定对应：

```text
研究线 i：Exploration_i ↔ Critic_i → Implementation_i → Verify_i

全局共享：Experiment Organizer、Boss Group、树形共享记忆
阶段报告：Paper Agent 接受 Boss Group 的报告任务
```

- Exploration Group 每组 m1 人，Critic Group 每组 m2 人，人数可配置；每条线配置一个 Implementation Agent 和一个 Verify Agent。
- 每个 Agent 使用完整 DSH；具体工具权限在功能确定后单独设计。
- Group 可以讨论和投票，保留意见、依据与分歧；科学上的研究方向与整体流程是否结束由全局 Boss Group 决定。人类立即终止与总时间到期的运行控制优先于所有 Agent 决策。
- Implementation Agent 负责实现、实际运行、监控与执行排错，不得自行修改研究方案。
- Organizer 决定何时运行、分配何种算力；批准时将任务返回对应 Implementation Agent，后者随即启动，无任务认领步骤。
- 默认 Implementation 的实现和运行报告可信。Verify 验证方案与结果的科学一致性、结论支持程度，不以防范实现者造假为目标，不复现实验、不重新运行大规模实验。
- 共享记忆仅由 Boss Group 维护；其他角色读取共享记忆，通过提交包提供观察与经验，不直接写入共享记忆。
- Paper Agent 撰写当前进展的实验报告，最终论文另设流程。

### 人类终止与唯一时间限制

- 人类可以在任何阶段立即终止研究，不需要 Boss、Organizer 或其他 Agent 同意；范围包括排队任务、正在生成的模型请求、工具进程、轻量计算和正式实验进程树。
- 收到终止请求后立即停止派发新工作、发出取消/终止指令，不等待实验自然完成、模型回复或本轮 Verify。只进行程序化清理与已有记录封包，不额外调用模型完成验证或报告。
- 数据库不可写或写锁阻塞时，独立停止通道仍须禁止启动并终止已登记执行，不能等待停止状态入库。停止记录在存储恢复后补写；记录不完整或控制服务重启后状态不明的研究禁止自动恢复。
- 保留终止前已存在的聊天、日志和实验产物；未完成验证标记待验证，不伪造结论、不增加 Verify 轮次。进程退出尚未确认时显示“正在终止/需处理”，不能误报全部已停止。
- 配置中只保留整个研究的 `max_runtime_seconds`。从实际启动计时，等待资源、暂停和重启间隔均计入；所有研究线共用同一个截止时间，到期执行与人类终止相同的停止流程。
- 不设置 token、费用、CPU/GPU 秒、单次/累计轻量计算、分实验预算，也不提供重试或讨论次数配额。错误分类、退避、科研方案本身的训练步数/重复次数/搜索范围仍然保留。
- 物理资源分配、角色权限和必要的协议/清理超时保留，用于正常调度与退出，不作为额外的研究预算。终止和到期不能被自动恢复绕过；继续研究需人类显式创建后续研究并重新设置总时间。

## 二、主流程与 Verify 周期汇报

以下为研究未终止、未到期时的正常流程；人类终止与总时间到期可在任一步骤抢占，按第一节封存待验证材料。

```text
Exploration_i ⇄ Critic_i
          │ 方案、实验设计和调整边界
          ▼
Implementation_i：实现代码，提交运行申请
          ▼
全局 Organizer：安排时机、分配算力，批准并返回任务
          ▼
Implementation_i：立即启动 → 持续监控 → 必要时修复或提前终止
          │ 完整结果或提前终止记录、Experiment Spec
          ▼
Verify_i：方案与结果验证，允许轻量 CPU 计算
          ├─ 达到第 k 轮：无论通过与否，直接交 Boss，不退回研究组
          ├─ 未到第 k 轮且通过：交 Boss
          └─ 未到第 k 轮且未通过：同时返回 Exploration_i 和 Critic_i

全局 Boss Group：研究判断、维护共享记忆
          ├─ 继续 / 补证据：交回对应 Exploration_i 和 Critic_i
          ├─ 放弃 / 换方向：保存经验，重置工作上下文，重新探索
          ├─ 阶段汇报：交 Paper Agent
          └─ 结束：结束方向或整体研究
```

### 轮次定义

为使“每 k 轮”可执行，本版采用以下计数口径：

- k 为可配置正整数，暂不预设具体值；各研究线独立计数，不等待其他研究线同步。
- 自 Boss 最近一次下发研究任务起，一份完整提交包完成一次 Verify 验证算一轮。首次启动从第 1 轮开始。
- 同一提交中的多个随机种子、Implementation 内部调试重试、Verify 的多次轻量计算不分别计轮；研究组修订后重新送验才进入下一轮。
- 第 k 轮完成验证后，无论通过或未通过，都将本轮提交包、验证意见及本周期历史摘要直接交 Boss；不同时退回 Exploration / Critic。后续由 Boss 决定。
- 未到第 k 轮的通过结果仍立即交 Boss。Boss 接管并下发下一轮任务后，开始新的计数周期。
- k=1 时，每轮验证后都交 Boss。研究线在周期内的失败记录不会因局部修订而清零。

### 执行错误与验证失败

- 执行错误由 Implementation 自行诊断和修复，保持方案固定项不变，并保留每次修复及重试记录。
- 需要改变研究方案时返回 Exploration / Critic 修订；需要改变算力分配时返回 Organizer 安排，不能自行占用未分配资源。
- 研究仍可运行时，完成、提前终止或最终无法完成的正式实验都生成结果/状态提交包送 Verify；没有完整结果也应说明原因。人类终止或总时间到期优先，仅封存已有材料并标记待验证，不继续发起 Verify。
- Verify 未通过时，按上述轮次规则分流；第 k 轮规则优先于普通的失败退回路径。
- 科学上的无提升、执行失败和提前终止分别记录，不相互等同。

## 三、角色功能

### 1. Exploration Group

- 查阅论文与共享记忆，提出研究问题、假设、方法和实验设计。
- 明确对照条件、预期观察、反对假设的证据，以及当前实验能回答的范围。
- 可以在研究总截止时间前做轻量 CPU 小规模验证，记录观察和局限；不另设单次与累计计算预算。
- 在实验计划中给出固定项、允许调整项及范围、运行监控要求和提前终止依据。
- 将方案、已有验证和待解问题交 Critic，处理其质疑。
- 接收未到第 k 轮时 Verify 返回的修订意见，或 Boss 下发的继续/补证据/换方向任务；不在第 k 轮绕过 Boss 自行开始下一轮。
- 将值得共享的经验写入提交包，交 Boss 决定如何纳入共享记忆。

### 2. Critic Group

- 检查已有工作、假设、比较公平性、混杂因素、证据缺口和运行计划。
- 可以在研究总截止时间前独立进行轻量 CPU 验证。
- 将质疑分成三类，并记录依据及处理方式：

| 类别 | 处理方式 |
|---|---|
| 必须修正 | 假设定义不清、比较不成立、实验无法回答问题等；修正后再进入实现 |
| 可以通过实验回答 | 对方法效果或机制存在经验性分歧；转化为对照、消融或反证实验，保留分歧后可以进入实现 |
| 建议改进 | 不影响当前实验成立的完善项；记录为后续建议，不阻塞本轮 |

- 与 Exploration 确认固定项、可调整范围及提前终止依据；不能仅因不相信方法会有效而无限阻止实验。
- 必须修正项处理完、可实验回答的分歧已纳入设计后，将方案交 Implementation；不要求对实验尚未回答的科学问题达成一致。
- 收到 Verify 的普通失败退回时，与 Exploration 一起修订，并说明各项意见如何处理。

### 3. Implementation Agent

- 按对应研究线的方案完成实现，记录代码、依赖、数据接口和启动方式；不自行改变研究方案。
- 将代码版本、实验计划及资源申请交 Organizer，等待其安排运行时机。
- Organizer 批准并返回任务后，使用分配的算力立即启动实验，无需再认领任务或寻找其他执行者。
- 负责监控运行过程、收集日志和指标，并根据计划及实际运行证据判断是否需要继续、修复或提前终止，具体见第五节。
- 发生实现或执行错误时，在固定项和允许调整范围内自行修复；研究未终止、未到期且资源授权有效时可重试，不必每次退回研究组，不设置累计重试次数预算。
- 不得以排错、节省算力或改善指标为由擅自更改固定项。超出调整范围时，向研究组提出修订需求；涉及资源改变时交 Organizer 安排。
- 运行结束或提前终止后，确认进程已退出并通知 Organizer 释放资源；研究仍可运行时将材料交 Verify，人类终止或到期时仅封存材料与待验证状态。
- 保留失败、修改和重试记录；不直接写共享记忆，不自行作出 Verify 的通过判断。

### 4. Experiment Organizer（全局）

- 接收各研究线 Implementation 的运行申请，分析算力、显存、时间、依赖与当前资源占用。
- 决定哪个实验何时运行，分配资源，批准后将任务返回原 Implementation；批准意味着可以开始运行，而非先批准后无限等待算力。
- 可以在内部使用队列或其他方法安排，具体机制留待实现阶段，不设计对外认领协议。
- 运行安排绑定任务、计划版本、资源范围和整个研究的截止时间；Implementation 修复代码仍需记录实际运行版本，Organizer 无权延长研究总时间。
- 处理需要改变资源分配的申请；接收结束或提前终止通知，安排后续实验。
- 不实际执行实验，不接管代码修复，不判断科学结论是否成立。

### 5. Verify Agent

- 与研究线固定对应，接收该线 Implementation 的提交包。
- 验证方案是否能回答研究问题，结果是否支持当前提出的结论，代码是否实现方案；结合实验计划和运行说明检查比较条件、实际调整、提前终止理由与结果适用范围。
- 允许读取已有产物并做轻量 CPU 计算，例如汇总已有指标、计算差异或不确定性、检查表格内部一致性；遵守整个研究的总截止时间，不另设计算配额。
- 默认结果可信，不重新训练、不复现正式实验、不重复跑大规模评估，也不把逐行实现审计作为常规职责。
- 验证报告写明：检查的问题、依据的产物、能支持的结论、尚不能支持的结论，以及通过/未通过的原因。通过只表示当前范围内方案和结果关系成立，不表示代码已被独立复现。
- 有效的无提升或负结果可以通过。提前终止的结果只支持已实际观察到的范围，不自动代表假设被否定或完整实验已经完成。
- 如果已有资料不足以支持当前结论，则明确未通过及缺口；不自行扩大验证为大规模实验。后续修订或补实验由研究组/Boss 按流转规则决定。
- 验证结论绑定具体计划、代码和运行记录，修改后的提交重新验证。
- 按第二节的 k 轮规则分流。向 Boss 汇报时保留未通过状态，不能因到了汇报轮次而改成通过。
- 不维护共享记忆；验证意见随提交包传递，由 Boss 统一整理。

### 6. Boss Group（全局）

- 接收普通轮次验证通过的提交，以及第 k 轮无论通过与否的周期提交。
- 根据验证意见、实验结果、累计尝试和资源消耗，判断继续、补证据、放弃/换方向、阶段汇报或结束。
- 对未通过的周期提交，可判断是否值得修订和继续投入，但不把未通过结果当作已获支持的科学结论。
- 继续或补证据的任务交对应 Exploration / Critic；后续正式实验仍经过 Implementation、Organizer、Verify。
- 负责所有共享记忆维护：选择条目、写入与修订、目录与摘要整理、冲突处理、版本与状态更新。
- 放弃方向时先保存实验历史及适用条件，再重置研究组工作上下文；不删除原始证据和共享记忆。
- 下发新任务时提供当前研究情况、相关共享记忆索引与研究优先级。
- 向 Paper Agent 下发阶段报告任务。汇报与继续研究可以同时发生，报告不等于方向完成。

### 7. Paper Agent（当前进展报告职责）

- 按 Boss 提供的提交包、验证报告与决策，撰写当前阶段的实验报告。
- 包含问题、方法、设置、实际结果、失败/负结果、提前终止、证据局限、Boss 判断与后续待办。
- 数字、图表和主要结论指向对应产物，区分已观察结果、解释性推断、验证未通过内容和待验证设想。
- 可以报告未通过或被放弃的尝试，但必须保留其状态，不把它们包装成可靠正面结论。
- 不直接维护共享记忆；最终论文的完整叙事、补充实验与投稿编排另行设计。

## 四、Experiment Spec、固定项与允许调整项

Experiment Spec 是贯穿研究设计、实现、运行和验证的统一提交包，Submission 为其目录或产物集合。Boss 收到的包同时包含 Exploration / Critic 设计、实验、结果与 Verify 意见；第 k 轮还包含本周期历史摘要。

### 提交包内容

| 内容 | 要求 |
|---|---|
| 标识与来源 | 研究线、方向/任务 ID、提交 ID、版本、父版本、作者、变更说明 |
| Exploration 设计 | 问题、假设、文献与记忆引用、方案、小规模验证记录 |
| Critic 意见 | 三类质疑、处理方式、纳入实验的分歧、后续建议 |
| 实验计划 | 固定项、允许调整项及范围、基线、数据、指标、变量、训练/搜索设置、重复/消融计划、研究总截止时间 |
| 监控与终止约定 | 监控信号、观察窗口、必要等待期、提前终止依据、异常处理、可恢复条件 |
| 实现与运行安排 | 代码版本、依赖、启动方式、Organizer 分配的资源与研究总截止时间 |
| 运行记录 | 运行 ID、实际配置、调整与修复、日志、指标、消耗、完成/提前终止/失败状态及原因 |
| Verify 验证 | 送验版本、检查依据、结论边界、通过/未通过、当前周期轮次 |
| 周期汇总 | 本周期历次验证、修订与资源消耗，第 k 轮提交 Boss 时一并提供 |
| Boss 决策与报告 | 研究判断、依据、后续任务、共享记忆更新引用、阶段报告 |

### 固定项

以下内容由 Exploration / Critic 在运行前确定，Implementation 不得自行改变：

- 研究问题、假设、方法的关键定义及本轮要比较的变量。
- 数据来源/版本、样本选择与过滤规则、训练/验证/测试划分和预处理语义。
- 基线、主要指标及计算口径、用于公平比较的训练步数/样本数等设置、评价频率中影响结论的部分。
- 训练目标、关键模型结构、优化器、有效 batch size、学习率及调度、数值精度等会影响科学结论的设置。
- 重复次数、随机种子策略、消融设计及模型/检查点选择规则。
- 方案的完成条件、提前终止判断规则及调整权限；均服从人类终止和研究总截止时间。

若本轮研究本来就包含参数搜索，搜索变量、候选集合/范围、搜索流程和选择规则属于固定计划；在该计划内执行候选配置不算修改方案。Implementation 不能根据结果自行扩大搜索空间。科学设置的固定性不等于另外建立一套可配置的资源预算。

### 允许调整项及范围

下表为默认边界。每份计划补充适用的具体数值或候选集合；没有明确允许的调整，不自动获得改变科学设置的权限。

| 项目 | 允许范围 | 越界处理 |
|---|---|---|
| 路径、临时目录、日志输出位置 | 限于指定工作区及产物目录，保持输入和产物身份不变 | 需要改变输入数据时返回研究组 |
| 日志缓冲、显示方式、非科学性进度信息 | 不丢失计划要求的监控、评估和结果记录 | 改变评估/模型选择规则时返回研究组 |
| CPU worker 数、读取并发、缓存 | 在计划允许范围与 Organizer 分配的资源内，不改变采样、顺序或计算语义；影响计时指标时须预先约定 | 无法满足等价性时返回研究组；更多资源交 Organizer |
| 实现错误修复 | 恢复既定方案的正确实现，不改变方法或比较条件；产生新代码版本 | 需要修改方案时返回研究组 |
| 同配置重试或恢复 | 研究未终止且未到期，遵守恢复/检查点规则和当前资源授权 | 需要重新分配资源时交 Organizer；总截止时间不能延长 |
| 计划允许的等价执行配置 | 仅使用预先列出的配置和条件；例如明确允许且不改变实验语义的内存优化方式 | 不得自行认定有效 batch size、精度或训练步数变化是等价修复 |

提前终止是结束当前运行，不是默许修改训练目标或比较口径。若要基于观察更换方案，在研究仍可运行时交研究组设计下一轮；人类终止或到期后不自动开启下一轮。

### 版本与交接

- 计划在相应运行开始前固定，计划改变产生新版本；代码修复也记录新版本。
- 一次计划可以关联多次运行；每次运行绑定实际使用的计划、代码及配置，保留失败和提前终止记录。
- 结果、评审和报告追加保存，不改写历史产物。
- 可以复制 Submission 交接，但须携带版本清单与完整性信息，记录接收版本；大文件可以使用带校验信息的稳定产物引用。

## 五、运行监控、提前终止与轻量验证

### Implementation 的运行监控

Implementation 负责在实验进行中观察状态，并决定是否有必要继续。监控应覆盖任务适用的信号，不固定为某一个指标或某一种趋势：

- 执行健康：进程异常、长时间无进展、输出缺失、非有限数值等。
- 时间与资源状态：是否接近研究总截止时间，以及实际内存/显存、进程健康与资源占用；消耗可记录展示，不作为分项预算扣减。
- 研究进展：计划关心的指标、收敛或稳定性、有效样本/迭代进度，以及实验是否仍能回答原问题。
- 结果可用性：当前产物能否支持后续分析，继续运行是否还有合理的信息价值。

### 提前终止原则

- Exploration / Critic 在计划中给出适用信号、必要等待期、观察窗口、容忍范围和终止依据；具体值随任务确定。
- Implementation 可以依据这些约定及实际运行证据提前终止，不必机械运行到研究总截止时间；人类终止和到期由程序直接执行。
- 区分正常波动、阶段性变化和持续异常；单次指标恶化不默认构成终止理由。某些方法的非单调过程应在方案中注明。
- 对计划未预见、但已使实验无法继续有效进行的执行或资源问题，可以停止并记录证据；不得据此自行改换研究方案。
- 若以“继续运行缺乏价值”为理由终止，说明观察到了什么、依据哪条计划或运行事实、尚不能判断什么；保留过程记录和已有产物。
- 结束后确认进程退出再通知 Organizer 释放/重新安排资源，保留终止原因、已用时间、已有结果和局限。研究仍可运行时提交 Verify，人类终止或到期时只封存并标记待验证。
- 记录所有提前终止的尝试，不只保留跑完或表现好的运行。正常研究中的 Verify 检查终止与结论的关系，不重新跑完整实验；人类终止或到期的材料保留待验证状态。

### 逐级验证与总运行时间

- Exploration、Critic 和 Verify 可以进行轻量 CPU 计算，只受整个研究的总运行时间限制，不设单次与累计计算配额。
- Exploration / Critic 用轻量验证检查想法和实验设计，Verify 用现有结果进行核对和分析；三者均不以重新跑正式大规模实验作为验证方式。
- 正式实验由 Implementation 执行，Organizer 决定运行时机与资源；不增加 Boss 逐个事前审批。
- 不要求先取得小规模正收益才允许大规模实验；需要规模才能观察的机制，应在设计中说明。
- 小规模验证记录也进入提交包；结果的证据范围与正式实验分别标明。

## 六、仅由 Boss 维护的树形共享记忆

树形目录用于组织与索引，按需读取；原始实验产物另存，不把整棵树加载到每个 Agent 的上下文。

```text
memory/
├─ index                 # 全局导航、研究方向和近期变化摘要
├─ research/
│  └─ topic/
│     ├─ index           # 方向概览及子节点索引
│     └─ hypothesis/
│        ├─ index        # 当前判断、关键证据和待解问题
│        └─ entries/     # 正结果、负结果、分歧及适用条件
└─ engineering/
   ├─ data/
   ├─ training/
   └─ runtime/
```

- **只有 Boss Group 可以写入、修订、整理或更新共享记忆，包括索引与摘要。**
- Exploration、Critic、Implementation、Verify 和 Paper Agent 可以读取；它们的本地笔记、实验日志与提交包不等于共享记忆。
- 其他角色将观察、经验、验证意见与来源放入提交包或向 Boss 提交记忆更新建议，由 Boss 选择和归纳；不得直接修改共享记忆。
- Boss 接到通过提交或第 k 轮周期提交后，结合完整记录更新记忆，失败和提前终止的经验也可以纳入。
- 条目记录适用条件、来源提交/运行、版本、原始贡献者及验证状态，Boss 的研究决策单独标注。
- 保留待验证、通过、未通过、争议、失效和被替代等状态；“放弃该方向”不自动表示科学假设已被否定。
- 读取顺序为全局摘要 → 相关方向摘要 → 条目 → 必要时原始证据，每层控制上下文量。
- 跨主题内容通过稳定 ID 与交叉引用关联，避免重复副本；冲突保留各自条件和证据，以新版本表达修订。
- 工作上下文重置不删除共享记忆与实验历史。

## 七、当前范围与后续事项

本阶段确定角色职责、研究线对应关系、实验约定、监控与终止责任、验证流转和记忆维护方式。

- Organizer 内部可以排队或使用其他调度方式，当前不限定实现。
- 多 Agent 的消息、状态持久化、进程监控机制、重启恢复、并发控制等程序实现不在本文展开，后续单独确定。
- 用户配置包括 n、m1、m2、k、Boss 人数和研究总运行时间，不设置各阶段预算、重试次数或讨论次数配额；各任务的监控窗口、科学终止条件和允许调整范围仍由方案明确。
- 角色权限的技术实现留待功能与实现方案确定后设计。

## 八、参考机制与边界

- [The Agentic Scientist / AI-Scientist-v3](https://arxiv.org/html/2610.18933v1)：借鉴任务契约、实验产物和主张证据对应。本设计默认实现可信，Verify 只进行方案与结果层面的验证，不照搬独立复现或完整实现审计。
- [AutoScientists 运行手册](https://github.com/mims-harvard/AutoScientists/blob/main/runbook.md)：借鉴研究设计与资源协调的职责分离。本设计由 Organizer 决定运行时机并将任务返回对应 Implementation，不采用 Agent 认领机制。
- [EvoScientist v2](https://arxiv.org/html/2603.08127v2)：借鉴研究经验和实验经验的区分及跨任务复用。树形索引与 Boss 独占维护是本设计的选择。
